# 自托管 runner 的运行侧部署

这个目录是**跑自托管 runner 那台机器上的东西**（宿主侧）。跟它配对的是容器侧：
`.ci/Dockerfile.pr-runner`（镜像）与 `.ci/runner-entrypoint.sh`（容器里的入口包装）。

整套东西要解决的问题：**让一个公开仓的自动审查跑在自己的机器上，而不把机器和内网摊出去。**
审查任务的内容来自任何人都能提的 PR，所以"不可信的内容要在我们自己机器上被处理"——
下面每个设计都在回答这一句。

## 结构

```
启动器 (launcher.py)          循环维持若干"待命容器"，每个容器只接一个任务
   └─ 起容器（参数写死，任务无权指定）
        └─ 一次性容器 = 审查环境 + GitHub 官方 runner
             └─ 跑完一个任务 → 容器销毁 → 启动器补下一个

宿主机网关 (gateway.py)       一个进程两个端口
   18080  按域名白名单转发 GitHub
   18081  把容器递来的假钥匙换成真 key，转发到模型网关
```

## 出口：两层，不是一层

容易说错的一点：不是"出口白名单有两项"，而是**容器只有一个出口，宿主机的网关再替它分两路**。

- **宿主机侧（pf 规则，见 `pf-setup.sh`）**：容器所在的网段只放行到宿主机的两个端口，其余一律丢掉。
  准确地说容器**能到的地址只有宿主机一个**——内网其它主机、公网都不通。
- **网关**：按域名白名单转发 GitHub，白名单外的域名 403；模型那一侧只转给一个模型网关。

容器里的两个环境变量就是这个形态：模型地址和 HTTP(S) 代理**都指向宿主机那一个地址**。

> ⚠️ 这道防线是**外部依赖**：pf 规则丢了就没了。所以 `launcher.py` 在起容器**之前会先实测**
> （起一个一次性容器探宿主机端口），封不住就拒绝起容器并报警——把静默失效变成显式失败。

## 凭据怎么进容器

一次性登记凭据**用 `container cp` 拷进容器文件系统**，不走命令行参数、也不走环境变量——
那两条路实测都会把凭据留在宿主上。`launcher.py` 里的注释记了四条被否掉的写法
（`ps` 可见、容器记录落盘、tmpfs 穿不进运行中的 VM、stdin 不转发）。

模型真 key 只在网关进程里；容器拿到的是一把**只在这个网关上有效的假钥匙**。

## 启动器还做什么

- **池子**：同时维持 `replicas` 个待命容器。每个一次性 runner 只接一个任务，所以并发 >1
  才扛得住多任务排队。
- **启动前两项自检**：出口（安全，见上）与网关存活（可用性）。少确认后者的话，容器会
  注册成功、领到任务、然后在审查时连不上模型，白吃一个任务。
- **内存准入**：补新槽前先看宿主可回收内存，低于阈值就不补。宁可少接活，也别把机器压进压缩/换页。
- **定期清理**：删已停止的容器、删无引用的镜像（**只在池子非空时做**，否则会把自己的镜像清掉）、
  删"离线且容器已不存在"的 runner 记录；容器被回收时也会**顺手删掉它那条记录**。

> 💡 容器在 `container system df` / `du` 里报的磁盘占用是**克隆 + 稀疏的账面数**，不是它独占的盘。
> 实测：删掉一个容器，卷上实际用量一点没降。所以"槽位数 × 每容器 2.4 GB"这个乘法是错的——
> 真正占盘的是**镜像堆积**（每次重建 +约 2.7 GB）。看容量请用 `df`。

## 怎么装

`pf-setup.sh`、`install-launchd.sh` 里都写了步骤与回滚。要点：

1. 建一个 host-only 容器网络（容器碰不到公网，只能到宿主机）
2. 写 `prreview.json`（照 `prreview.example.json` 改；凭据只以**文件路径**形式出现在配置里）
3. `pf-setup.sh` 装出口过滤，然后 `--persist` 让它开机生效
4. **取镜像**：`python3 pull_image.py` —— 从 ghcr 拉。包是 public 就零凭据
   （公开仓出来的镜像没有秘密，正常就是把它设成 public）；私有包才需要
   `registry_token_file` + `--login-user`。脚本会把 digest 打出来，好写进配置钉死。
5. `install-launchd.sh` 装两个常驻服务（网关 + 启动器）

## 已知限制

- **依赖 macOS 的 pf 与 launchd**，且**开机不会自动启用 pf**，所以需要那个 LaunchDaemon。
- **单点**：宿主机的网关是容器的唯一出口，它挂了审查就完全跑不动（启动器会因此拒绝起容器）。
- **绑定一个容器运行时的网络形态**：这套的前提是"容器能到宿主机、但到不了别处"。换运行时前要重新验证。
- 镜像里装审查 CLI 的那一步**不固定版本**（为了跟上游），已在注释里标为有意为之。
